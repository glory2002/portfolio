The Challenge

A platform built to last — maybe too long

The platform had been in production for over 10 years. It worked — but it looked like it was from another era. Small fonts, dense tables, inconsistent button styles, no visual hierarchy. The business couldn't afford a full rebuild, so the goal was clear: make the interface dramatically better without touching the backend.

Every page was a slightly different interpretation of the same interface. Agents moving between modules had to re-learn the UI each time. Critical actions sat alongside low-priority links with identical styling.

"It gets the job done, but I spend half my day looking for things that should be obvious."

— Insurance Agent, User Interview

Design Process

How I approached the redesign

01

CSS strategy with the front-end team

The project kicked off with a working session with the front-end team. The stylesheets had become inconsistent and hard to maintain over the years — together we defined a clear strategy for restructuring the CSS before any visual work began.

02

Exploring directions in Figma

I created 2–3 design concepts for the main screen and presented them to the product and engineering teams. We selected a direction that balanced modernization with the visual identity already familiar to users.

03

Visual identity & component system

I preserved the platform's existing green but refreshed it to feel more modern and accessible. I introduced a product logo (the platform had none), redesigned the header layout, and defined a full token system — colour, typography, spacing — before touching any screens.

04

Login page & key screen redesign

Starting with the login page and the highest-traffic modules, I redesigned each screen in Figma then implemented the changes through the CSS/Less layer — no backend changes, no HTML restructuring.

05

QA & cross-browser testing

Tested across Chrome, Firefox, Edge, and IE11. Resolved 23 visual inconsistencies in edge-case states — empty tables, long text overflow, multi-line labels.

Design System

Building the component library in Figma

Alongside the visual redesign, I built a structured component library in Figma covering all the building blocks of the platform — typography, color tokens, form elements, accordions, cards, tables, and tree components. This ensured consistency across screens and gave the front-end team a clear reference for implementation.

After — Modernized UI

Outcome

Results

Following a phased rollout to the full agent team, the product owner shared feedback and early usage metrics:

40% reduction in time-on-task for the claim approval flow — measured via session recordings before and after
0 backend changes required — the entire transformation was delivered through the CSS/Less layer only
9 / 10 average satisfaction score from agents in a post-launch survey — up from 4/10 before the redesign

Takeaway

Constraints as a design brief

Working within an unchangeable HTML structure forced me to focus entirely on the visual layer — typography, colour, spacing. Defining the design system upfront made implementation fast and consistent. The biggest lesson: enterprise users have strong mental models, so the goal was to make things feel familiar but dramatically cleaner — not reinvent the interaction model entirely.
