Challenge

The problem

Tanya was teaching through PHI Academy and using their Craft Master platform. It worked — but it wasn't hers. She had no control over branding, content structure, or the student experience. As she grew her own name, she needed a platform that reflected her standards.

  • Limited control over content and student experience.
  • No personalised feedback system — corrections were manual and untracked.
  • No branded learning environment — everything lived under another brand.
  • No way to issue certificates, track progress, or manage enrolment independently.

Key takeaways

Structured, level-based courses work — but they need a real feedback loop to validate skill progression.

Community and mentorship are missing from most platforms — direct instructor access is a differentiator.

No existing tool combines learning + direct feedback + branded certification in one place.

Opportunity: Create a platform that combines structured learning, real-time feedback, and branded certification — tailored to Tanya's teaching methodology.

Concept

The solution

TH Academy is a private, invite-only learning platform built around Tanya's teaching method. Two distinct roles — instructor and student — share the same system but experience it differently. The platform moves each student through structured levels, with direct feedback at every stage and a certificate waiting at the end.

Instructor

Tanya Hristova

  • Creates and structures courses by level
  • Invites students individually
  • Reviews submitted work and leaves feedback via chat
  • Tracks student progress across all courses
  • Issues certificates upon completion
Student

Enrolled learner

  • Accesses courses through a personal invite
  • Progresses level by level at their own pace
  • Submits practical work for review
  • Receives real-time corrections in chat
  • Downloads a certificate on course completion

Development

System logic & development

The product is not only screens — it is rules: who can do what, when a level unlocks, and how instructor and student stay aligned. I defined that logic with the client, then implemented it in code (React, Vite, Supabase) with Cursor as my primary dev environment, so design decisions stayed traceable all the way to behaviour in production.

Cursor

Cursor let me move quickly from structure in Figma to real components, state, and API calls. I could iterate on flows, tighten copy, and adjust edge cases in the same session — without losing the thread between UX intent and implementation detail.

Level logic

Each course is a sequence of levels with explicit status (e.g. locked, in progress, submitted, approved). A student only unlocks the next level after the instructor approves the current one — mirroring how Tanya actually teaches, not a generic “complete video → next” pattern.

Cross-role communication

Instructor and student never share the same UI, but they share the same data model: enrolment, level state, messages, and certificates. Realtime chat per level is the feedback channel — submissions, corrections, and approval all leave a trail both sides can trust.

  • Role-based system (Instructor / Student)
  • Level unlocking based on approval
  • Feedback loop via chat

Design system

Modular foundation

A disciplined system keeps student and admin experiences visually aligned while the codebase stays maintainable as features grow.

Design-to-code continuity

I created a modular design system and connected it directly to the application, allowing real-time updates across the product.

That is not a handoff PDF that drifts from production — it is shared tokens and components (colours, type scale, spacing, UI primitives) reflected in both Figma and React. When a token changes, the shift propagates everywhere the system is applied.

Develop

Designing the system

04

Visual direction

Neutral gray and black palette — professional and calm, appropriate for a learning environment. Warm gold accents reserved for progress indicators and certificates. Typography kept clean and legible at all sizes, given the content-heavy nature of the platform.

05

Course workspace layout

The most critical design decision: a three-panel workspace with a fixed left sidebar (course outline + level statuses), a scrollable center panel (theory content), and a fixed right panel (chat with instructor). All three needed to be visible simultaneously on desktop, while collapsing gracefully on mobile.

06

Component system

Built a full Figma component library: status badges with 5 states, course level cards, chat message types (student/instructor, text/image, correction request), certificate templates (Basic vs Masterclass), admin data tables, and mobile navigation patterns.

Deliver

What shipped

07

Automated onboarding flow

Admin creates student → automated email invitation sent → student sets password and activates account. Zero manual steps for the instructor after the initial setup.

08

Realtime feedback loop

Student submits work via chat → status moves to "For Review" → instructor approves or returns for correction with structured feedback → student sees update in realtime. Each level tracks its own correction history.

09

Certificate generation

On course completion, a branded certificate is generated automatically — with different templates for Basic and Masterclass tracks. Print-ready and shareable.

Reflection

What I learned

This was the most systems-level UX challenge I'd worked on — not designing pages, but designing a machine with interlocking states. The status model for course levels turned out to be the single most important design decision: get it wrong, and the entire feedback loop breaks down for both users.

The three-panel workspace required constant trade-offs between information density and cognitive load. Several iterations went too far in each direction before landing on a layout that felt genuinely usable under real learning conditions.

Having a technical background helped enormously — understanding how realtime subscriptions work, how Supabase RLS affects what each user can see, and how the database schema shapes the UI made me a much more effective design partner.

If I extended this project further, I'd focus on the student dashboard — a clear overview of where they are across all levels, what needs their attention, and how close they are to their certificate. Progress visibility is the feature most likely to improve completion rates.
