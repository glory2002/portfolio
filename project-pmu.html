Cover — hero / platform screenshot

Overview

TH Academy is a custom learning platform for permanent makeup training: structured levels, per-assignment feedback, and branded certification — aligned with how the instructor actually teaches.

The work spanned research and UX flows through UI, a shared design system, and build support in code so the experience stays consistent from marketing site to student dashboard.

The product is delivered as a Progressive Web App (PWA) — a website that can be installed and used in an app-like way (e.g. from the home screen) while remaining a responsive web experience. Roughly 95% of students use it on their phones; the instructor’s admin and review flows are also phone-first day to day, alongside a full desktop layout for longer course authoring and administration.

Challenge

The problem

PHI Academy + Craft Master worked. Not her brand. Not her rules. She needed her own platform.

  • No real control over content or UX.
  • Feedback manual, untracked.
  • Everything under someone else's brand.
  • No own certs, progress, or enrolment.

Concept

The solution

I designed a custom LMS that enables structured progression, real-time feedback, and certification through a dual role system.

Information architecture

Instructor · admin

Student · academy

Courses · card grid #/a/courses
ShowsTitle, cover, status (draft / published / archived), dates, enrollment count.
ActionsEdit · duplicate · archive · publish · delete · new course.
My courses #/s/courses
ShowsTitle (mirrors admin), progress / level, access state, continue vs locked, pending-review banner.
ActionsOpen · continue · profile.
Course · structure & content #/a/course/:id
ShowsLevels (order, title, lock), theory blocks, sections (text / media), course metadata.
ActionsLevel edit · section edit · preview (modal) · save · back.
Course · workspace #/s/course/:id
ShowsLevel outline, theory for active level, tasks & uploads, instructor chat thread, level status.
ActionsSubmit for review · chat · next level · back to courses.
Students · table #/a/students
ShowsName / avatar, email, course IDs, added date, account status, training & feedback status.
ActionsInvite · row actions (aligned with roster workflows).
Profile · dashboard #/s/profile · #/s/dashboard
ShowsContact, enrollments, per-course progress, certificate when complete — statuses match admin table.
ActionsDashboard · profile · certificate · logout.

Wireframes

Design system

Reflection

What I learned

Systems UX: interlocking states, not pages. Level status model = linchpin.

Three-panel layout = density vs. calm. Many passes to feel right in real study sessions.

Tech literacy helped: realtime, RLS, schema ↔ UI.
